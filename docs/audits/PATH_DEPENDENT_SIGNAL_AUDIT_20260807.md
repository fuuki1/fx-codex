# 経路依存型シグナル監査（全decision対象）

**作成日:** 2026-08-07
**対象:** 15m / 1h の方向性 decision 全件（建玉されたものだけではない）
**コード:** `[DEV]` HEAD `60e2c51`
**⚠️ PRODは未変更。** 実機DBと tick tape を読み取り専用で参照しただけである。

---

## なぜ全decisionを見るのか

これまでの4調査は**建玉された54件**だけを対象にしていた。しかし実測では
**15,134 decision のうち建玉は 62 件（0.41%）**しかない。
建玉されたものだけを見るのは生存者バイアスであり、
「シグナルに情報があるか」には答えられない。

本監査は、**建玉されなかった decision も含めて**、各 decision が自身の
stop/target のもとで tick 経路上どうなったかを評価する。

---

## 結論

**1. シグナルには方向性の情報が検出できない。**
非重複サンプル eff n=549 で平均 **−0.0783R**、95%CI **[−0.374, +0.249]**。
建玉54件での結論（`GROSS_EDGE_DECOMPOSITION_20260807.md`）が
**約37倍の有効標本でも再現された。**

**2. conviction（確信度）は成績と単調な関係を持たない。**
0-20帯が **+0.153R**、20-40帯が **−0.279R**、40-60帯が **+0.380R**。
順序が壊れており、確信度が高いほど良いという関係が無い。

**3. リスク拒否ゲートは弱いながら正の選別をしている。**
`opened` 平均 +0.046R に対し `abstained` −0.035R。
ただし eff n=24 では有意でない。

**4. ⚠️ 本監査の初版には重大な欠陥があり、途中で2度修正した（§2）。**

## 2. ⚠️ 初版の欠陥と修正（重要）

**最初の実行では平均 −3.69R、1h では −12.13R、最小値 −2025R が出た。**
1時間の EURUSD がリスクの2000倍動くことは物理的にあり得ない。
これは市場の事実ではなく**当方の手法の欠陥**だった。

### 2.1 価格ソースの不一致

decision の `close`/`stop`/`target` は **TradingView の終値**基準だが、
tick tape は **Dukascopy** である。両者は数pips乖離する。

実例（decision `5a731b85dcd16855d9b3`, EURUSD 1h long, 2026-08-03T01:18）:

| 項目 | 値 |
|---|---|
| decision の close（TV） | 1.15382 |
| 同時刻の tick（Dukascopy） | 約 1.15330 |
| **乖離** | **5.2 pips** |
| decision の stop | 1.153420 |

→ stop が **decision close と tick の間**に位置するため、
tick 価格で建てた long は**建玉時点で既に stop を割っている**。
R の分母が潰れて値が発散する。

**これはこのリポジトリで既知の問題である**
（memory: `tight_stop_price_source_mismatch_20260730`
「SL短縮の副作用: 判断closeと実tickが10-14pips乖離」）。

### 2.2 修正1: 建玉時点の妥当性ゲート

**結果の大小で除外すると事後選択になる**ため、
t0 時点の**幾何**で判定するゲートを入れた:

```
long : entry <= stop  または entry >= target なら棄却
short: entry >= stop  または entry <= target なら棄却
```

→ 263件を棄却。しかし **−2025R が残った。**

### 2.3 修正2: microstructure floor

残った原因は、entry が stop の **2.6e-7 内側**にあり、
順序判定は通過するが分母がほぼ0になるケースだった。

P0-C（`classify_sizing_invariants`）と同じ floor を適用した:

```
realised risk < 2 x spread なら棄却
```

→ さらに169件を棄却。

### 2.4 修正の効果

| | 初版 | 修正後 |
|---|---:|---:|
| 最小 horizon_r | **−2025.07** | **−29.14** |
| 最大 horizon_r | +424.48 | +45.18 |
| 全体平均 | −3.6924 | **−0.0783** |
| 1h 平均 | −12.1321 | −0.1998 |

**初版の「1h は −12R」は完全な誤りであった。**

### 2.5 棄却の内訳（409件 = 17.0%）

| 理由 | 件数 |
|---|---:|
| microstructure_floor（実効リスク < 2×spread） | 169 |
| price_source_mismatch（entry が target を超過） | 122 |
| price_source_mismatch（entry が stop を超過） | 100 |
| ticks 不足 | 18 |

**⚠️ 棄却率17%自体が所見である。** decision の価格基準と実 tick が
これだけ乖離しているなら、decision の stop/target は
**実際には意図した位置に無い**可能性がある。

## 3. 重複の扱い（方法論）

decision は5分間隔で生成されるが、horizon は 15〜60分である。
したがって連続する decision は**同じ将来窓を共有**する。

| timeframe | horizon | 重複する decision 数 |
|---|---:|---:|
| 15m | 15分 | 3 |
| 1h | 60分 | **12** |
| 4h | 240分 | 48 |
| 1d | 1440分 | **288** |

生の n をそのまま使うと証拠を大幅に水増しする
（memory: `effective_samples_opposite_sign_bug_20260728`）。

**本監査は、各 (symbol, timeframe) で horizon 長より短い間隔の decision を
除外した非重複部分集合に対してのみ CI を計算する。**
4h/1d は eff n が 14 / 2 程度にしかならないため**対象から外した**。

| conviction | eff n | 平均R | 勝率 | 95%CI |

| 0–20 | 190 | **+0.1528** | 45.8% | [−0.304, +0.668] |

| 80–100 | 0 | — | — | — |

**単調性が無い。** 最低帯（0-20）が中位帯（20-40）を上回っている。

conviction の実測レンジは **6〜77**（中央値25）で、
80以上は一度も出ていない。

これは memory の `cs329a_applicability_and_inverted_calibration_20260806`
（Brier 0.318 > base 0.247 で確信度が有害）と整合する所見である。

**⚠️ ただしどの帯も CI が0を含み、単独では有意でない。**

## 7. 言えないこと

1. **「シグナルに情報が無い」と断定はできない。** eff n=549 で
   CI 幅が ±0.3R あり、小さいエッジは検出できない
2. **因果関係ではない。** 同一 tick 経路上の事後計算である
3. **コスト控除前である。** net ベースではさらに約 −0.14R 下がる
   （`SPREAD_COST_ATTRIBUTION_20260807.md`）
4. **棄却された409件は評価不能であり、無害とは限らない。**
   むしろ decision の価格基準そのものに問題がある可能性を示す
5. **4h / 1d は未評価。** 重複が大きすぎて本手法では扱えない

## 9. 次に測るべきこと

### 9.1 価格ソース乖離の実態調査（最優先・新規）

本監査で**17%が評価不能**になった。原因は decision（TradingView）と
tick（Dukascopy）の価格乖離である。これは
**シグナル品質以前のデータ整合性の問題**であり、
`GAP` 文書の Data Truth Plane に属する。

測るべきこと:
- decision close と同時刻 tick の乖離分布（通貨・時間帯別）
- 乖離が stop/target 配置をどれだけ意図から外しているか

### 9.2 conviction 較正の本格評価

§5 は示唆的だが eff n が足りない。
4h/1d を含めた全 decision で、重複を考慮した較正曲線を引く必要がある。

**⚠️ target パラメータの直接最適化は依然として行わない。**
本監査は「方向に情報が無い」ことを再確認したのみで、
target を動かす根拠にはならない。

## 付録: 手法

```
entry  = 最初の tick の executable 価格（long=ask, short=bid）
R      = (executable - entry) * sign / |entry - stop|
決済    = tick を時系列走査し stop/target 先着（同一 tick なら不利side優先）
horizon = 15m -> 15分, 1h -> 60分
```

ローダは `fx_intel.virtual_portfolio_replay.load_quote_tape`。
反実仮想 replay で実決済理由を **18/18 再現**した実績がある。
